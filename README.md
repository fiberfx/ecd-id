# ecd-id

The Ecd ID, eid for short, version 1: a 16-byte identifier that names the system that minted it, the kind of thing it names, the
Unix millisecond of the mint, the writer and a count. Its one text form is 28 lowercase characters:

```text
emq_job_23obzcbapvupu2272222      system emq, kind job, 2026-11-21T14:30:00.123Z, writer 895287301, count 0
```

- **Ordered.** Text order equals byte order: system, kind, time, writer, count.
- **Minted locally.** A producer holds a lease (one writer number and a window of id-time) and mints with no round trip
  per id. Two ids of one registered system are never equal while the allocation premises hold.
- **Strict.** One case, one spelling, fixed length, no aliases; every refusal has a named reason.
- **Stream ids.** Each id maps to a Valkey stream entry id `<ms>-<system<<48 | writer<<18 | count>`, unique across
  systems that share a stream, and back again given the stream's kind.
- **Retired code.** The code `brd` is retired: its row stays in the registry, and nothing mints under it. Its ids are
  embeddings of brd14 ids, computed both ways without a table ([spec/registry.md](spec/registry.md#brd14)).

## Go module

The module path is `github.com/fiberfx/ecd-id/go`; the package name is `eid`. Go requires the version tag of a module in a subdirectory to carry its path, so the module's versions are the tags `go/vX.Y.Z`, beside the repository's own `ecd-id-vX.Y.Z` tags.

```sh
go get github.com/fiberfx/ecd-id/go@vX.Y.Z                 # in go.mod: require github.com/fiberfx/ecd-id/go vX.Y.Z
go install github.com/fiberfx/ecd-id/go/cmd/eid@latest     # the command
```

```go
import eid "github.com/fiberfx/ecd-id/go"
```

`ID` implements `encoding.TextMarshaler` and `TextUnmarshaler`, `driver.Valuer` and `sql.Scanner`, and `json.Unmarshaler`,
so an id is stored and sent without a wrapper; `NullID` serves nullable columns and JSON `null`. The zero `ID` is refused
when encoded, and a JSON null is refused when decoded into an `ID`; a missing JSON field leaves an `ID` unchanged, so
nullable or optional fields use `NullID`. The encodings refuse with `zero` (the zero ID encoded, or JSON null decoded
into an ID), `scan-type` (a Scan source that is not []byte) and `json-type` (a JSON value that is neither a string nor,
for NullID, null).

`Role` is the role of a kind ([spec/registry.md](spec/registry.md#roles)). Its ten values are the constants
`RoleEntity`, `RoleActivation`, `RoleCommand`, `RoleRun`, `RoleStream`, `RoleStore`, `RoleDatabase`, `RoleTransaction`,
`RoleCorrelation` and `RoleRequest`, each the text of its role in `kinds.tsv`; the loader refuses any other text with
`registry-role`. `Registry.KindsByRole(system, role)` returns the kinds of one system that have the role, in code order
and in every state, as `KindsOf` does, and none for a system without a row or a role outside the list. Rust's
`Role` enum names the same ten roles; Rust has no `kinds_by_role`.

## Running the checks

```sh
(cd model && go run . --check)               # the committed vectors equal the model's output
(cd rs && cargo test --release)              # Rust: conformance and behaviour
(cd go && go test ./...)                     # Go: conformance and behaviour
(cd go && go build ./cmd/eid)                 # the command, as ./eid
sh rows/eid.rows.sh                          # every gate as one row, each with its control, and the builds of eid
sh rows/eid-ts.rows.sh                       # TypeScript: bun test over the vectors, tsc --noEmit, mutants
sh rows/eid-py.rows.sh                       # Python: unittest over the vectors, brd14, mutants
```

`(cd model && go run .)` regenerates `vectors/`.

Test names carry the property they check: Rust tests start with `g1_` to `g11_` and `g14_`, Go tests with `TestG01` to
`TestG14`, and the registry tests with `registry_` and `TestRegistry` (they include the kind-only check of detached ids, that every kind of a retired system is retired, and in Go the role constants and `KindsByRole`); `g12` and `g13` exist in Go only.

| Prefix | Property |
|---|---|
| `g1` | Vectors: both directions, and every invalid input refused with its reason |
| `g2` | Order: random ids sort the same as text and as bytes; an unsorted alphabet does not |
| `g3` | Burst: unique and strictly rising per writer under load; borrowing past 262,144 in a millisecond |
| `g4` | Stream ids: distinct across systems on one writer and millisecond; the inverse; Valkey's append rule |
| `g5` | Restart: an allocator restarted many times, some inside one second, never reissues a live writer |
| `g6` | Clock set back and store restored: no repeat with a correct clock; repeats counted when both faults meet |
| `g7` | Fenced clone and the pid guard |
| `g9` | mxdb identities |
| `g10` | The door: detached ids bound as command tokens, never stored as the system's own |
| `g11` | One-case text |
| `g12` | The file store: the record is on disk, one activation per system, 2 processes × 1,000 grants give 2,000 distinct writers; the control without the lock repeats them (Go only) |
| `g13` | The command `eid`: its output, exit status and refusals against `vectors/cli.tsv`; stores, `eid lease`, detached ids (Go only) |
| `g14` | brd14 ids: every row of `vectors/brd14.tsv` both ways, pure and through the registry layer, with every refusal; byte order equals brd14 order; random ids return |

Each property has a violating case beside its good case: a control input that the check refuses, or a fault whose
effect the test counts. The Rust test `g4_valkey_live` runs against a Valkey server when `EID_VALKEY` names its
address (`127.0.0.1:6399`); without it, the stream tests check the arithmetic against Valkey's documented append
rule.

The Linux container of the rows cannot check directory names on a case-folding file system (NTFS, APFS); there the
`g11` tests assert that every canonical text in the vectors is one case, so no two of them can fold together.
`rows/eid-casefold.sh` makes the check on such a host: one directory for each distinct id text of the vectors, and a
control that the file system folds case. On APFS, measured on 24 Nov 2026: 400 distinct id texts gave 400 directories,
and the upper-case twin of one id opened its directory.

On APFS, measured on 22 Nov 2026: creating one directory for each of 2,428 mixed-case KAN document ids made 2,355
directories, because ids that differ only by letter case name one directory; creating one for each of the 2,428
corresponding Ecd ids made 2,428. NTFS is not measured.

## A home host

A host that runs a system's supervisor (a system whose `home` in `registry/systems.tsv` names that host) is set up
once:

- the binary `eid` at `~/.local/bin/eid`;
- the registry, a copy of a released `registry/` kept outside any shared mount;
- the store, a directory outside any shared mount, one for the home;
- `EID_HOME` (the host's own name in the registry), `EID_STORE` and `EID_REGISTRY` (the two directories), set only in
  that host's own launch environment, such as its shell profile or its service manager's unit. A supervisor takes no
  lease unless all three are set ([spec/registry.md](spec/registry.md)).

A process takes its lease with `eid lease SYSTEM --store "$EID_STORE"` ([spec/cli.md](spec/cli.md)).

## Status

Version 1 holds the format, the reference model, the vectors and the Rust and Go libraries. An Elixir library, generated
kind constants and subsystem adoption are out of scope for version 1; the tree holds no Elixir code.

The TypeScript package (`ts/`) and the Python package (`py/`) follow the same vectors with a narrower scope: they parse,
format and convert ids, leases and stream ids, and embed brd14 ids; they do not mint and hold no registry. Both are
private until a publish is decided.
