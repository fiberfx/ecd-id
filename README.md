# ecd-id

The Ecd ID, eid for short, version 1: a 16-byte identifier that names the system that minted it, the kind of thing it names, the
Unix millisecond of the mint, the writer and a count. Its one text form is 28 lowercase characters:

```text
emq_job_23obzcbapvupu2272222      system emq, kind job, 2026-11-21T14:30:00.123Z, writer 895287301, count 0
```

- **Ordered.** Text order equals byte order: system, kind, time, writer, count.
- **Minted locally.** A producer holds a lease (one writer number and a window of id-time) and mints with no round trip
  per id. Two ids of one registered system are never equal while the allocation premises hold.
- **Strict.** One case, one spelling, fixed length, no aliases; every refusal has a named reason.
- **Stream ids.** Each id maps to a Valkey stream entry id `<ms>-<system<<48 | writer<<18 | count>`, unique across
  systems that share a stream, and back again given the stream's kind.
- **Retired code.** The code `brd` is retired: its row stays in the registry, and nothing mints under it.

## Running the checks

```sh
(cd model && go run . --check)               # the committed vectors equal the model's output
(cd rs && cargo test --release)              # Rust: conformance and behaviour
(cd go && go test ./...)                     # Go: conformance and behaviour
(cd go && go build ./cmd/eid)                 # the command, as ./eid
sh rows/eid.rows.sh                          # every gate as one row, each with its control, and the builds of eid
sh rows/eid-ts.rows.sh                       # TypeScript: bun test over the vectors, tsc --noEmit, mutants
```

`(cd model && go run .)` regenerates `vectors/`.

Test names carry the property they check: Rust tests start with `g1_` to `g11_`, Go tests with `TestG01` to
`TestG13`, and the registry tests with `registry_` and `TestRegistry` (they include the kind-only check of detached ids); `g12` and `g13` exist in Go only.

| Prefix | Property |
|---|---|
| `g1` | Vectors: both directions, and every invalid input refused with its reason |
| `g2` | Order: random ids sort the same as text and as bytes; an unsorted alphabet does not |
| `g3` | Burst: unique and strictly rising per writer under load; borrowing past 262,144 in a millisecond |
| `g4` | Stream ids: distinct across systems on one writer and millisecond; the inverse; Valkey's append rule |
| `g5` | Restart: an allocator restarted many times, some inside one second, never reissues a live writer |
| `g6` | Clock set back and store restored: no repeat with a correct clock; repeats counted when both faults meet |
| `g7` | Fenced clone and the pid guard |
| `g9` | mxdb identities |
| `g10` | The door: detached ids bound as command tokens, never stored as the system's own |
| `g11` | One-case text |
| `g12` | The file store: the record is on disk, one activation per system, 2 processes × 1,000 grants give 2,000 distinct writers; the control without the lock repeats them (Go only) |
| `g13` | The command `eid`: its output, exit status and refusals against `vectors/cli.tsv`; stores, detached ids (Go only) |

Each property has a violating case beside its good case: a control input that the check refuses, or a fault whose
effect the test counts. The Rust test `g4_valkey_live` runs against a Valkey server when `EID_VALKEY` names its
address (`127.0.0.1:6399`); without it, the stream tests check the arithmetic against Valkey's documented append
rule.

Version 1 does not check directory names on a case-folding file system (NTFS, APFS); the `g11` tests assert instead
that every canonical text in the vectors is one case, so no two of them can fold together.

On APFS, measured on 22 Nov 2026: creating one directory for each of 2,428 mixed-case KAN document ids made 2,355
directories, because ids that differ only by letter case name one directory; creating one for each of the 2,428
corresponding Ecd ids made 2,428. NTFS is not measured.

## Status

Version 1 holds the format, the reference model, the vectors and the Rust and Go libraries. Elixir and TypeScript
libraries, generated kind constants and subsystem adoption are out of scope for version 1.
